# Copilot instructions for this repository

## Build, test, and lint commands

- Primary scripts (package.json):
  - npm run schema        -> node src/introspect.js
  - npm run procs         -> node src/document-procedures.js
  - npm run deps          -> node src/document-dependencies.js
  - npm run guide         -> node src/generate-guide.js
  - npm run descriptions:sql -> node src/generate-ms-description-sql.js
  - npm run descriptions:check -> node src/validate-descriptions.js
  - npm run test:connection -> node src/test-connection.js
  - npm start             -> node src/index.js

- There are no automated test suites or linters in this repo. For a quick syntax check use:
  - node --check <file>

## High-level architecture

- Node.js utility that connects to an Azure SQL Server (uses the `mssql` package) and generates Markdown documentation of databases.
- Core modules (src/):
  - src/db.js               — single shared ConnectionPool helper
  - src/introspect.js       — main schema introspector & Markdown renderer (per-db, per-table/view, SCHEMA.md)
  - src/document-procedures.js — procedure/function doc generator
  - src/document-dependencies.js — cross-database dependency scanner and renderer
  - src/generate-guide.js   — curated EDS_GUIDE.md generator (uses descriptions.json)
  - src/generate-ms-description-sql.js — emit apply-descriptions.sql
  - src/validate-descriptions.js — sanity-check descriptions.json keys
  - src/test-connection.js  — connectivity probe

- Outputs (regenerated by scripts):
  - SCHEMA.md, EDS_GUIDE.md, apply-descriptions.sql
  - docs/tables/<db>/..., docs/procedures/<db>/..., docs/dependencies/<db>/...

## Key conventions and repo-specific patterns

- Direct SQL catalog queries: the code queries INFORMATION_SCHEMA and sys.* directly (no ORM/query builder).
  - Database names are bracketed into cross-database queries (e.g. [${db}]). Only trust names sourced from sys.databases or curated lists; do not accept unvalidated user input.

- Generated docs are disposable and overwritten by scripts:
  - npm run schema wipes and recreates docs/tables/
  - npm run procs wipes docs/procedures/
  - npm run deps wipes docs/dependencies/
  => Do not hand-edit generated files.

- Filenames use safeSegment(): non-alphanum characters are replaced with `_`. Keep link helpers in sync with file builders to avoid broken links.

- descriptions.json is the curated source for MS_Description text:
  - Keys for objects: <db>.<schema>.<object>
  - Keys for columns: <db>.<schema>.<object>.<column>
  - Run npm run descriptions:check before trusting a batch of descriptions.

- When adding metadata, extend inspect*() to return it on the info object and thread that through renderers (avoid re-querying inside renderers).

## Environment & running

- Copy .env.example -> .env and fill DB_SERVER, DB_USER, DB_PASSWORD, etc.
- DB_DATABASE in .env only sets the initial context; introspection scripts still iterate all online user databases.

## Where to look for more guidance

- AGENTS.md and CLAUDE.md at repository root contain detailed operational notes and generation rules. Read them before changing introspection/rendering logic.
